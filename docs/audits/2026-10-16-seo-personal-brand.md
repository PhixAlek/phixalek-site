## Dónde debe aparecer cada cosa

- **Home:** nombre real, alias, rol principal, especialidad C#/.NET + Angular y proyectos. El título local actual, `Alejandro Segura — Software Developer | PhixAlek`, es una base clara. No necesita incorporar todos los temas.
- **About:** experiencia y proyectos reales; enseñanza, estudios y áreas de aprendizaje explicados con precisión. Separar experiencia actual de lo que se está explorando.
- **Writing:** una descripción breve del enfoque y enlaces a publicaciones reales. No añadir una lista extensa de keywords en el encabezado.
- **Artículo:** título centrado en un problema, introducción que responda a ese problema, encabezados semánticos, código/ejemplos propios, imágenes con alt útil, referencias y enlaces a contenido relacionado.
- **Autor:** vincular cada artículo con la misma entidad Alejandro Segura / PhixAlek y los perfiles propios ya enlazados. No alternar identidades ni inventar credenciales.
- **Proyectos:** mostrar la evidencia de las tecnologías mencionadas. Un artículo sobre una decisión de Flowly debe enlazar al proyecto o repositorio relevante.

Para artículos en español, usar títulos naturales en español; para inglés, inglés. No traducir solo el título o la descripción para simular una edición traducida. No crear hreflang sin versiones equivalentes accesibles por URL.

## Etiquetas y crecimiento del blog

Mantener los tipos existentes **Notes, Thoughts, Guides**. Son formatos; no cargos ni tecnologías. Usar un tipo y los temas pertinentes, sin etiquetar todos los posts con todas las tecnologías.

Los temas existentes permiten comenzar sin inflar los filtros:

- C# / .NET: backend y ecosistema .NET.
- Angular: frontend Angular y TypeScript cuando corresponda.
- Architecture: arquitectura, límites y System Design.
- Software: prácticas, testing y entrega; puede servir inicialmente para CI/CD, SQL o Docker según el artículo.
- AI: integración y evaluación de IA.
- Game Dev: C++, Unreal, procesos de juego y assets.
- Design: diseño, UX o diseño visual cuando realmente sea el asunto del post.
- Web Dev: contenido web transversal.

Azure, Docker, SQL, TypeScript, Testing o Blender pueden convertirse en etiquetas específicas cuando existan publicaciones que las justifiquen. No se añaden filtros vacíos ni se cambia ahora el sistema de categorías. Una etiqueta ayuda a navegar; no crea automáticamente una página SEO indexable ni garantiza posicionamiento.

## Cómo evaluar resultados

Tras publicar el SEO, usar Search Console para separar consultas de marca (Alejandro Segura, PhixAlek) de consultas de tema y revisar la página que recibe impresiones. Medir URLs indexadas, impresiones, clics y consultas reales; no interpretar la ausencia de tráfico inicial como prueba de fallo técnico ni prometer fechas de posicionamiento.

Antes de decidir nuevas páginas o categorías, comprobar si ya hay contenido suficiente y si los usuarios buscan esos temas. No hay datos de volumen, competencia o conversiones disponibles en esta revisión.

Google no usa `meta keywords` para ranking. Añadir términos a `knowsAbout` o al JSON-LD tampoco reemplaza publicaciones y proyectos que demuestren el tema. Los datos estructurados deben describir el contenido, sin convertirse en un catálogo de aspiraciones.
